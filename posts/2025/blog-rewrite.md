## 为什么离开 xLog

近两年，我一直在 xLog 上写博客。xLog 是一个基于区块链的去中心化博客平台，理念很美好，但随着时间推移，它逐渐不再适合我了。

**首先，xLog 已经停止开发。** 作为开发者，我深知一个不再维护的平台意味着什么——没有新功能、没有 bug 修复、没有性能优化。更重要的是，Web 技术发展很快，一个不再迭代的平台会逐渐落后于时代。

**其次，平台上充斥着低质量内容。** 去中心化的理念固然美好，但缺乏内容审核机制导致内容质量参差不齐。我希望博客是一个纯粹的技术分享和生活记录空间，而不是被营销号和低质量内容包围。

**最后，也是最重要的——我需要更多定制化功能。** xLog 的功能相对固定，无法满足我的个性化需求。

比如，我想要一个「碎碎念」功能，记录每天的小想法、小确幸。我还想要一个「Mio 说」板块，这是一个专属的记录空间。这些功能在现成的平台上都难以实现。

## 为什么选择自己开发

离开 xLog 后，我面临两个选择：使用现成的博客平台（如 WordPress、Ghost），或者自己从零开发。经过权衡，我最终选择了自己开发。

### 混合渲染：静态与动态的平衡

选择 Next.js 不是因为它流行，而是因为它的 App Router 让我可以同时拥有静态和动态的优势。

文章列表和详情页通过静态生成（SSG），构建时就生成好了 HTML，访问速度极快。同时，我又能写 API Routes 来动态更新内容——比如通过 GitHub Action 调用 API 添加碎碎念，不需要重新构建整个站点。

这种混合模式在传统博客平台很难实现。要么完全静态，更新需要重新构建；要么完全动态，性能受影响。而 Next.js 让我鱼和熊掌兼得。

React 19 的编译器自动优化了组件的重渲染，省去了手动 memo 的麻烦。Tailwind CSS v4 的 CSS-first 配置让样式管理更简单，不需要配置文件。这些都是实实在在能提升开发效率的功能。

AI 辅助开发也帮了大忙。比如这篇文章，就是我和 Claude Code 一起完成的——我提供想法和技术判断，Claude 帮我整理表达。很多重复性的代码工作交给 AI，让我能把精力放在设计和体验优化上。

托管选择 Vercel，运行成本几乎为零。它的边缘网络让全球访问都很快，自动优化图片和资源，还有实时的构建预览。最重要的是免费额度对个人博客完全够用，唯一的成本是域名费用，一年也就一百块钱左右。

### 完全掌控

最重要的是，**我拥有对博客的完全掌控权**。可以根据需求随时调整技术方案，可以尝试新的技术实践，可以优化任何想优化的地方。

所有代码都在我的 GitHub 仓库中，可以随时查看、修改、备份。这种掌控感，是任何第三方平台都无法提供的。

当然，自己开发也需要投入时间和精力。但对我来说，这个过程本身就是一种技术实践和能力提升，值得投入。

## 设计理念：简约中的温度

在设计这个博客时，我一直在思考一个问题：如何让一个技术博客既保持专业简洁，又能承载生活的温度？

### 极简主义：黑白灰的纯粹

博客的主体设计非常极简——只使用黑、白、灰三种颜色。没有花哨的动画，没有复杂的交互，只有纯粹的文字和内容。

这种极简设计不是偷懒，而是一种克制。见过太多为了炫技而堆砌功能的项目，最终都因为过度复杂而难以维护。好的设计应该是做减法，只保留最核心、最必要的元素。

我希望读者的注意力能集中在内容本身，而不是被花哨的设计分散。但极简不等于冷漠。在保持整体简洁的同时，我为生活化的内容添加了一些色彩。

### 黑白灰与粉色：理性与温馨

这是整个设计中我最喜欢的部分。

博客的主体和「碎碎念」都保持黑白灰的极简设计——这代表着理性和专业，无论是技术文章还是日常记录，都统一在这种克制的色调中。

唯一的例外是「Mio 说」。这个板块使用粉色作为点缀——不是因为 Mio 喜欢粉色，而是因为粉色代表着温馨和柔软。当我在设计这个板块时，我一直在想：什么样的颜色才能代表这个空间的氛围？最后选择的是一种温柔但不失存在感的粉色——在亮色模式下是温暖的粉，在暗色模式下是柔和的粉。这个选择经过了多次调整和对比，直到找到那个「刚刚好」的色调。

这种设计不仅仅是视觉上的区分，更是一种氛围的营造：

- 博客主体和碎碎念的黑白灰，代表着理性和专业
- Mio 说的粉色点缀，代表着温馨和专属

当你打开「Mio 说」页面，页面中的标题、线条等元素使用粉色点缀。那一刻，你会感觉到这个空间的氛围不一样——温馨、柔软、专属。

### 阅读体验：让文字呼吸

文章的宽度、行高、字间距，都经过仔细调整。合适的行宽（65-75 个字符）、舒适的行高（1.6-1.8）、恰当的字间距——这些数字背后是科学研究和用户体验的最佳实践。

移动端的体验也很重要。响应式设计不是简单的媒体查询，而是针对不同设备特性做针对性优化。小屏幕上字体会稍微大一点，交互区域会更大，导航会更简洁。移动设备是很多人的主要阅读场景，体验必须做好。

### 一些小心思

有些优化可能不容易被注意到，但它们确实存在：

- 所有外链都会自动添加 ↗ 图标，提示这是一个外部链接
- 链接使用虚线下划线，鼠标悬停时切换为实线
- 主题切换时没有闪烁，过渡非常平滑
- 超过一年的旧文章会自动显示提示横幅，告知读者内容可能过时
- 每篇文章都会自动计算阅读时间

这些小心思可能不会被所有人注意到，但我知道它们在那里。就像生活中的很多小事，不需要被看见，但它们让一切变得更好。

## 特殊的功能设计

### 碎碎念：记录生活的点滴

「碎碎念」是我为自己设计的功能。它不是传统的博客文章，而是类似 Twitter 的短内容——记录生活中的点滴想法、小确幸、突然的灵感。

有时候是一句话，有时候是一段观察，有时候只是一个感叹。这些内容不需要长篇大论，不需要完整的逻辑，只需要记录下那一刻的感受。

支持小时级别的更新，意味着我可以随时记录。早上起床时的想法，中午吃饭时的观察，晚上睡前的感慨——它们都会被保留在这里。

### Mio 说：粉色点缀的专属空间

「Mio 说」是这个博客中比较特别的功能。

这个板块使用粉色作为视觉点缀，标题、线条等关键元素采用粉色，在黑白灰的基调上营造出一种温暖的氛围。这种克制的用色方式，既保持了整体的简洁，又让这个板块有了独特的辨识度。

技术上，这个板块的内容管理权限是独立的。内容通过 GitHub 添加，这是一种通过代码实现的权限分离。

这个设计的初衷是想打造一个独立的记录空间，让内容能够被完整地保留，不被随意修改或删除。

### 大事记：时间线上的记录

大事记记录重要的时刻和里程碑。有些是技术上的，比如博客重写完成、新功能上线；有些是生活上的重要时刻。

每条记录都包含日期和描述，按时间线排列。这不是流水账，而是那些值得被记住的瞬间。时间会流逝，记忆会模糊，但这些记录会一直在这里。多年以后翻看这些大事记，能想起那些时刻的感受和心情。

## 设计中的取舍

在开发过程中，我做了很多选择和取舍。

### 为什么不用数据库

最初我考虑过使用数据库来存储内容，但最终选择了更简单的方案——用文件存储。

这个决策看似简单，实际上是经过深思熟虑的。数据库固然强大，但它带来的复杂度和维护成本，对于这个博客来说是不必要的。过度设计的危害很明显——不是每个项目都需要微服务，不是每个应用都需要数据库。

文件存储的好处是：所有内容都是纯文本文件，可以用任何编辑器编辑，可以用 Git 管理版本。不需要担心数据库服务器的问题，不需要担心数据丢失，一切都很简单可靠。这种简单性本身就是一种优势。

唯一的缺点是无法提供原生的评论功能，但我可以集成第三方评论系统来解决。不是什么都要自己做，知道什么时候该借助外部服务也很重要。

### 为什么不用复杂的内容管理系统

市面上有很多功能强大的内容管理系统，比如 WordPress、Ghost、Strapi 等，但我选择了最简单的方案——直接用文件系统。

我希望写作的过程是简单的、自然的。打开编辑器，写下想法，保存，提交到 Git。不需要登录后台，不需要填写表单，不需要点击各种按钮。所有内容都是 Markdown 文件，可以用任何编辑器打开，可以用 Git 追踪每一次修改。

这样的写作体验最接近于在纸上写字——简单、直接、纯粹。作为开发者，我深知复杂系统的维护成本。能用简单方案解决的问题，就不要引入复杂度。而且，这种方式还有个额外的好处：内容完全属于自己，不会被任何平台锁定。

## 写在最后

从 xLog 迁移到自建博客，对我来说不仅是技术上的尝试，更是一次完整的实践。

在这个博客的设计中，我发现技术不应该仅仅服务于技术本身。好的设计应该服务于目的，而不是为了技术而技术。

最让我满意的是「Mio 说」页面的设计。每次打开，看到标题和线条上那温暖的粉色点缀，会感觉到这个空间的氛围——温馨、独立、专属。这个颜色的选择不是随意的，而是经过深思熟虑的设计决策。

技术是工具，但用技术打造的空间可以很温暖。代码可以被复制，但设计背后的思考和用心，却是独一无二的。

如果你也在考虑自建博客，不妨想想：你想通过这个空间表达什么？你想要什么样的氛围？技术选型应该服务于这些目标。

技术不是最重要的，重要的是你想通过技术实现什么。但掌握技术，能让你更自由地表达。
